## Next version

**Breaking API changes:** The way raw parameters are passed to the underlying libraries was tweaked and namespaced.

- The Three.js raw getters are now grouped under [`ThreeLayer.three`](api/index.md#three-1):
    - `threeLayer.getScene()` => `threeLayer.three.getScene()`
    - `threeLayer.getRenderer()` => `threeLayer.three.getRenderer()`
    - `threeLayer.getCamera()` => `threeLayer.three.getCamera()`
-  Changes to [`ThreeLayer.load3dTiles()`](api/index.md#load3dtiles):
     - Previously: `threeLayer.load3dTiles({tilesetUrl, ..., maxDepth, preprocessURL})`
     - New API: `threeLayer.load3dTiles({tilesetUrl, ..., tilesRendererOptions: {maxDepth, preprocessURL}})`
- `new ThreeDManager({..., dracoPath,ktx2Path});` became `new ThreeDManager({..., tilesRendererConfig: { dracoPath, ktx2Path }});`
- `ThreeDTilesOffset` was renamed to `MetersOffset`.

**Nonbreaking additions:**

- It is now possible to pass raw Three.js options when calling [`ThreeDManager.createLayer()`](api/index.md#createlayer). Example:
    - `threeDManager.createLayer({three: {rendererOptions: {...}}})` 
- `load3dTiles()` now has an [`autoLoaders`](api/index.md#autoloaders) boolean which can be set to `false` to control the loaders and extensions directly.

**Bug fixes:**

- A tile asset's `getReference()` function now takes tile offset into account.
- Local dev server now only binds to localhost.
- Bilinear interpolation now works properly on the edges of the raster (wraps around longitude, clamps latitude).
- Bilinear interpolation unit test does not make CDN network calls anymore.
- Hide `ThreeLayer` on low zooms in globe projection to prevent rendering the scene with the wrong projection.

## 1.0.0 - 2026-09-25

This version introduces *breaking* API changes and major internal refactors.

The concept of a layer is now separate from the concept of a 3D Tiles asset. A layer can contain multiple assets, including 3D Tiles and any raw Three.js object. This is the crux of the change. Below is a high-level overview of the biggest changes.

- **Full Three.js support:** Raw Three.js primitives can now be accessed via a layer, allowing any Three.js rendering on the map, not just 3D Tiles.
- **Multiple layers:** Multiple independent Three.js layers can be added to the MapLibre map, allowing fine-grained depth control if needed.
- **Multiple 3D Tiles:** Multiple assets can be added to the map, in the same layer or in separate layers.
- **Helper functions:** Helper functions are exposed via `ThreeDManager`, allowing conversions between the different coordinate systems.
- **Raycasting:** Exposed the necessary helper functions and performed internal refactors to allow proper raycasting. There is now a raycasting example in the code repository.
- Layer ids are now optional. An id will be autogenerated if not supplied.

## 0.0.10 - 2026-09-15

- Support for vertical datums
- Breaking API refactor: explicit `manager.init()`, `manager.createLayer()`, and `layer.load3dTiles()`. Pass layers directly to MapLibre; multiple assets share a scene and render pass.
- ECEF placement for ordinary Three.js objects, sea-level altitude conversion, and east/up/south orientation helpers.
- Scene, camera, renderer, and tiles-renderer getters; coherent camera matrices for raycasting and world-coordinate conversion helpers.
- Per-asset east/up/south offsets use a fixed reference derived from the root bounding volume.
- Detach/reattach support and ownership-based asset/layer/manager teardown.

## 0.0.8 - 2026-07-29

- Rendering depth updates. The default behavior is now exactly MapLibre-style-like where the layer order in the style dictates the depth. Exposed depth controls; the user can now optionally render "interlaced" layers if they want to:
  - on `getLayer()`, one can optionally specify whether to clear the depth before/after the current layer (both default to `true`).
  - exposed a "separator" custom layer that renders nothing and clears the depth.
