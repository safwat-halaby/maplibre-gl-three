## NEXT

This version introduces *breaking* API changes and major internal refactors.

The concept of a layer is now separate from the concept of a 3d tile asset. A layer can contain multiple assets, including 3dtiles, and including any raw threeJS object. This is the crux of the change. Below is a high level overview of the biggest changes.

- **Full ThreeJS support:** Raw ThreeJS primitives can now be accessed via a layer, allowing any threeJS rendering on the map, not just 3dtiles. 
- **Multiple layers:** Multiple independent ThreeJS layers can be added to the MapLibre map, allowing finegrained depth control if needed.
- **Multiple 3dtiles:** Multiple assets can be added to the map, in the same layer or in separate layers.
- **Helper functions:** Helper functions are expose via `ThreeDManager`, allowing convertions between the different coordinate systems.
- **Raycasting:** Exposed the necessary helper functions and performed internal refactors to allow proper raycasting. There is now a raycasting example in the code repository.
- Layer ids are now optional. An id will be autogenerated if not supplied.

## 0.0.10 - 2026-09-15

- Support for vertical datums
- Breaking API refactor: explicit `manager.init()`, `manager.createLayer()`, and `layer.load3dTiles()`. Pass layers directly to MapLibre; multiple assets share a scene and render pass.
- ECEF placement for ordinary Three.js objects, sea-level altitude conversion, and east/up/south orientation helpers.
- Scene, camera, renderer, and tiles-renderer getters; coherent camera matrices for raycasting and world-coordinate conversion helpers.
- Per-asset east/up/south offsets use a fixed reference derived from the root bounding volume.
- Detach/reattach support and ownership-based asset/layer/manager teardown.

## 0.0.9 - 2026-09-06

- Migration to maplibre-gl 6

## 0.0.8 - 2026-07-29

- Rendering depth updates. The default behavior is now exactly Maplibre-style-like where the layer order in the style dictates the depth. Exposed depth controls; The user can now optionally render "interlaced" layers if the want to:
  - on `getLayer`, one can optionally specify whether to clear the depth before/after the current layer (both default to true).
  - exposed a "separator" custom layer that renders nothing and clears the depth. 

## 0.0.7 - 2026-07-22

- renamed `preprocessUrl` to `preprocessURL` and fixed a bug which caused this parameter to be ignored.

## 0.0.6 - 2026-07-19

- Exposed `maxDepth` in `load3dTiles`.
- Fixed typos in "Plate Carree".
- Various DX tweaks
  - Restrict OSM maxzoom in examples
  - Rename mislabeled natural-earth layer
  - CDN consistency - all URLs now use https://jsdelivr.net
  - Inlined a 3dtiles + natural earth dataset up to zoom 3 for complete offline development.

## 0.0.5 - 2026-07-16

- Typescript support.
- Exposed an optional `preprocessUrl` callback for `load3dTiles`, allowing the user to modify the URLs before 3dtile resources are requested.
- Added some support for plate carree slippy tiles, with some caveats that will be better documented later. 
- Internally, we now call `clearDepth` before rendering to resolve some visual artifacts.
